# Memory 工具优化复测

更新日期：2026-07-28

动态回放首次达到 100% 阶段+行动参考一致率后，Trace 仍显示 21 次工具执行中有
10 次 `memory_read` 返回空结果。根因有两个：

1. 模型使用公司名或岗位名作为自由查询词，过度收窄当前机会历史。
2. OpenAI-compatible 中转站偶尔忽略工具 Schema 的枚举，在只开放 L1 时仍请求 L2。

改动：

- 删除 Memory 工具的自由查询字段，只读取首轮尚未展示的当前机会历史。
- 同一记忆层每个 run 最多执行一次。
- 只有一个合法记忆层时，协议层将非法层规范化到唯一合法值并记录 Trace。
- 将模型请求数、实际执行数和拦截重复数分开统计。

同一 41 个真实会话、57 个增量轮次复测：

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 最终阶段+行动一致率 | 100.00% | 100.00% |
| 实际工具执行 | 21 | 11 |
| 空工具结果 | 10 | 0 |
| LLM 调用 | 42 | 42 |
| Agent Token | 112,402 | 104,917 |

在质量不回退的前提下，实际工具执行减少 47.62%，空调用全部消除，Agent Token
减少 6.66%。模型服务延迟存在网络波动，因此本次优化主要以工具执行、空结果和 Token
衡量，不把单次墙钟时间包装成稳定 SLA。
