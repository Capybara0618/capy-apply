# Capybot Apply 动态追踪 A/B 报告

> 使用脱敏真实 L1 数据，在隔离 PostgreSQL `capybot_apply_benchmark_dynamic` 中按发言轮次回放。
> 参考集为 LLM 双标注裁决集，不是人工 Gold Set。

## 实验设计

- 会话：40；动态增量轮次：57。
- Agent：只输入本轮新增消息、上一轮机会投影，并按需读取 Memory/岗位/Skill。
- One-shot：每轮重新输入截至当前的全部消息、岗位卡和全部 Skill。
- 两组使用同一模型、JSON Schema 和 CommitGate。
- 本轮通过 `--offline` 关闭外部 MCP，仅验证可重复的上下文管理。

## 结果

| 指标 | 增量 Agent | 全量 One-shot |
| --- | ---: | ---: |
| 最终阶段+行动一致率 | 100.00% | 62.50% |
| LLM 调用数 | 42 | 105 |
| Token | 104917 | 309030 |
| 累计模型处理时间 | 363.549s | 992.412s |
| 工具调用数 | 11 | 0 |

- 40/57 个轮次由 `DecisionRouter` 以 0 LLM 完成。
- Token 减少 66.05%。
- LLM 调用减少 60.00%。
- 累计模型处理时间减少 63.37%。
- Agent 请求 17 次工具调用，实际执行 11 次，拦截 6 次重复请求；空结果 0 次，
  2 次调用的新证据进入最终决策。

## 边界

- 质量指标只在每个会话最终时间点计算，中间状态没有冒充人工 Gold。
- 当前样本量有限，数字用于项目内对照，不宣称生产泛化准确率。
- 外部 MCP 的可用性由独立真实集成实验验证。
