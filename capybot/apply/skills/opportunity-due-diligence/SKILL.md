# 调查岗位机会

## 工作流

1. 列出会改变求职决策的事实缺口或冲突，只调查职责、用工主体、地点、薪资、实习周期和明确风险。
2. 先读取 Memory 与本地岗位证据，区分“未提供”“相互冲突”和“已有风险证据”。
3. 本地职责或条件不完整时调用 `boss_fetch_job_detail`，比较 HR 表述与版本化岗位快照。
4. 只有公司主体、业务或招聘关系仍会影响判断时调用 `research_company`；公开网页只作为 `web_source` 证据。
5. 工具没有返回可靠来源时保留未知状态，不把“未查到”解释为安全，也不把工具错误解释为岗位风险。
6. 输出已确认事实、冲突、风险、仍缺信息和一个最关键的 HR 追问；证据不足时使用 `verify` 或 `needs_review`。

## 工具策略

- `memory_read`：检查历史说法和状态变化。
- `job_read`：读取本地岗位卡与岗位快照。
- `boss_fetch_job_detail`：补充当前 BOSS 岗位的完整职责和条件。
- `research_company`：核验公司业务、主体或招聘关系。

每次只调用能改变当前决策的最小工具。获得岗位详情后先重新判断，不默认继续查询公司。

## 完成标准

- 明确区分事实、冲突、未知和推断。
- 外部结论必须引用 `boss_job_snapshot` 或 `web_source`。
- 风险建议说明其对继续、核实或关闭决策的影响。
- 最终问题具体可回答，不使用泛化的“能详细介绍一下吗”。
