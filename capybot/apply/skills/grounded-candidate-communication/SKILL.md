# 生成有依据的候选人回复

## 工作流

1. 提炼 HR 当前真正需要回答的一个核心问题，区分项目能力、个人经历、到岗条件和材料说明。
2. 读取 Memory，避免否认历史承诺、重复发送材料或遗漏尚未回答的问题。
3. 读取候选人画像，只选与问题直接相关的一至两个事实；岗位要求中出现但画像没有的能力不得写成候选人经历。
4. 回复需要与具体职责对齐时先读本地岗位证据；只有完整岗位要求会改变回复内容时才补取 BOSS 岗位详情。
5. 将信息分成“已有证据”和“需要用户确认”。到岗时间、实习周期、薪资等缺少证据时生成确认任务，不替用户承诺。
6. 生成直接回答问题的中文草稿，并为每项个人经历、行动和草稿绑定 canonical evidence ref。

## 工具策略

- `memory_read`：核对历史聊天、材料和承诺。
- `profile_read`：获取脱敏简历事实、技能和项目。
- `job_read`：读取本地岗位要求。
- `boss_fetch_job_detail`：岗位要求缺失且会影响回答重点时补查。

优先使用本地事实。不要为了让回复更长而调用工具；读取到足以回答的问题后立即停止。

## 回复标准

- 结论在前，项目证据随后，只回答 HR 当前问题。
- 不使用待填写占位符，不声称掌握画像中不存在的技能。
- 不伪造已发送材料、到岗承诺或量化结果。
- 系统只生成待确认草稿，绝不写入或发送 BOSS 消息。
