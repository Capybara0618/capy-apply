# 准备岗位面试

## 工作流

1. 从 HR 消息与 Memory 核对日期、时间、形式、地点、会议平台和未确认事项。条件性表述不能直接升级为 `interviewing`。
2. 优先读取本地岗位证据；只有职责或要求不完整且会改变准备重点时，才补取 BOSS 岗位详情。
3. 读取候选人画像，将岗位要求映射到一至两个真实项目。不得补写画像中不存在的技能、职责或量化结果。
4. 只有公司业务会影响技术准备时才查询公司；不要为了展示工具调用而搜索。
5. 生成一份紧凑简报：面试安排、岗位重点、项目映射、高概率问题、准备任务和待确认信息。
6. 需要回复 HR 时，同时生成任务与草稿；草稿只确认已知安排或询问一个关键缺口，不声称已经自动发送。

## 工具策略

- `memory_read`：核对历史承诺、安排和已发送材料。
- `job_read`：读取本地岗位卡与版本化岗位快照。
- `boss_fetch_job_detail`：本地岗位要求不足时补证据。
- `profile_read`：选择候选人的真实项目和技能。
- `research_company`：仅补充会改变准备内容的公司业务事实。

每次调用前先说明缺少什么以及新事实将改变哪项准备；新事实不能改变产物时停止调用。

## 完成标准

- 面试阶段、确认草稿和准备任务均有 canonical evidence ref。
- 准备内容能够对应具体岗位要求，而不是通用面试清单。
- 项目映射只引用候选人画像中的事实。
- 信息仍有冲突时输出待确认问题，不编造安排。
